## AGENTS.md 在项目中的作用

### 不应该写什么 - 这些应均在for-agents中统一描述

- 一般的回复风格、代码风格、脚手架规范

### 应该写什么

**1. 项目定位与目标（Project Context）**

- 项目是什么，解决什么问题
- 核心功能和主要使用场景
- 项目的设计目标（Goals）
- 项目当前所处阶段及重要背景
- 功能交付验收标准

**2. 项目架构（Architecture）**

- 整体架构及核心模块划分
- 模块之间的依赖关系
- 核心数据流和调用链
- 关键组件的职责边界
- 重要的架构设计决策及其原因

**3. 项目特有约束（Project Constraints）**

- 不允许修改的模块或文件
- 必须保持的兼容性
- API、数据结构、协议方面的约束
- 特殊的技术选型限制
- 必须遵守的业务规则
- 不允许引入的依赖或技术

**4. 开发与运行环境（Environment）**

- 项目依赖的特殊环境
- 必须使用的运行时、SDK 或工具链版本
- 特殊的环境变量及其用途（不包含真实密钥）
- 本地开发、测试、构建所需的前置条件
- 特殊的服务依赖及启动顺序

**5. 项目操作指南（Project Workflows）**

- 如何启动项目
- 如何运行测试
- 如何执行构建
- 如何进行数据库迁移
- 如何生成代码或资源
- 特殊的部署和发布流程

普通命令可以简单引用脚本，不需要重复解释脚本已经完成的事情

**6. 关键目录与文件说明（Repository Map）**

- 特殊目录的用途
- 关键入口文件
- 配置文件的职责
- 自动生成文件的位置
- 需要特别注意的文件

不需要把整个目录树抄一遍，只记录 Agent 无法直接从文件名判断的信息

**7. 跨模块协作规则（Integration Rules）**

- 模块之间如何协作
- 哪些接口属于稳定边界
- 修改一个模块时需要同步考虑哪些模块
- 跨仓库依赖和协作关系
- 共享资源的所有权

**8. 已知问题与风险（Known Issues & Risks）**

- 已知技术债务
- 当前未解决的问题
- 容易引发回归的区域
- 特殊的测试盲区
- 不应该重复尝试的失败方案

**9. 代办清单与工作计划（Todo List）**

- 尚未完成的项目部分

### 参考模版

```markdown
## Project Context

项目定位、目标

## Architecture

整体架构、核心模块及其职责

## Project Constraints

项目特有的限制

## Environment

特殊开发环境及运行依赖

## Workflows

项目启动、测试、构建、部署等操作

## Repository Map

关键目录、入口文件及特殊配置说明

## Integration Rules

模块边界、接口约定及跨模块协作规则

## Known Issues & Risks

已知问题、技术债务和潜在风险

## Todo List

代办清单
```
